# GitHubとZenodoでの公開計画

GitHubを、研究計画、本文、実験コード、評価条件の変更履歴を持つ作業場所として使う。区切りのよい版をZenodoへ保存し、引用できる固定版にDOIを付ける方法を検討する。

GitHubの公式案内では、publicリポジトリをZenodoへ接続し、リリースごとにアーカイブと新しいDOIを作成できる。連携の設定と許可は、版を保存する段階で行う。出典: [GitHubの引用と参照](https://docs.github.com/en/repositories/archiving-a-github-repository/referencing-and-citing-content)、[ZenodoのGitHub連携](https://help.zenodo.org/docs/github/)。

## 今回の範囲

publicリポジトリに、研究計画と実験前の下書きを置く。Zenodo連携、正式なリリース、DOI取得、論文PDFの投稿は含めない。

## 最初の固定版の条件

- 著者表記と引用メタデータを確定する。
- 再利用のライセンスを記録する。
- 先行研究の比較と、主張の根拠を対応させる。
- 設計案と測定結果を区別する。
- 実験結果を載せる場合は、条件、原記録、再現手順を添える。
- 配布物に鍵、個人情報、第三者の再配布不可資料を含めない。

設計段階の公開を行う場合は、研究提案またはプロトコルとして表題と説明をそろえる。結果がない状態を、実験済み論文として公開しない。
